# Связь рабочих, алгоритма и интерфейса

Маршруты доступны вошедшим пользователям, задачи и результаты привязаны к пользователю.
Рабочие и квалификации читаются из локальной копии PostgreSQL, синхронизированной
модулем `infra_loader`. Демо-данные в обычном режиме не используются.

| Запрос | Результат |
|---|---|
| `GET /api/workforce/employees` | Полные записи `employee` с массивом `qualifications` |
| `POST /api/brigades/jobs` | HTTP 202, новая или уже выполняющаяся задача пользователя |
| `GET /api/brigades/jobs/current` | Последняя задача или `null` |
| `GET /api/brigades/jobs/{id}` | Статус, стадия, прогресс и результат задачи |
| `GET /api/brigades/result` | Последний успешный результат или `null` |

## Куда вставлять алгоритм

**Единственная точка вызова: `algorithm_adapter.py`, функция `solve(problem)`.**

Сейчас она запускает существующий `algorithm/solver.py` через CLI в отдельном
процессе: максимум 200 000 итераций, 150 секунд поиска, жёсткий timeout процесса
170 секунд. Матрица конфликтов пока нулевая. Для замены алгоритма достаточно
изменить `solve`, сохранив контракт:

```python
def solve(problem: dict) -> tuple[dict, dict]:
    # Вставьте вызов своего алгоритма здесь.
    # problem = {"employees": [{"tabel": 1, "qualifications": {"water": 5.0}}, ...],
    #            "incidents": [{"event_id": 101, "object_id": 10, "resource": "water",
    #                           "base_duration_seconds": 3600, "occurred_at": "...+03:00"}, ...],
    #            "precedences": [[101, 102], ...]}
    return m2_document, diagnostics
```

`m2_document` строго содержит `brigades` с `brigade_id`, `employees`, `event_order`.
`diagnostics` — отдельный отчёт; в экспорт M2 он не попадает. Приложение повторно
проверяет составы/события/квалификации и считает интервалы по выходному M2 с помощью
`algorithm.solver.evaluate`. При подключении матрицы конфликтов передавайте одну
и ту же матрицу в алгоритм **и** серверный оценщик в `service.build_result`, обновите
метку `conflictModel`. Иначе интервалы будут рассчитаны с K=0.

`data.prepare` собирает согласованный снимок под общим lock импорта: последнее
состояние объекта/ресурса на момент начала планирования, только активные аварии,
базовые времена в секундах и транзитивные зависимости в рамках ресурса. Наивные
времена источника трактуются как московские. Планирование начинается сейчас;
смещения результата переводятся в ISO 8601. Если активных аварий нет, возвращается
пустой результат без вызова алгоритма. Некорректный вход возвращает HTTP 422.

## Жизненный цикл

Прогресс во время поиска неопределённый (`null`), вместо выдуманного процента.
API отвечает сразу и доступен во время расчёта. Одновременно выполняется один расчёт
на процесс приложения; повторный POST того же пользователя возвращает его задачу.
Текущая конфигурация рассчитана на один процесс uvicorn.

SQLite сохраняет последний успешный результат; ошибка следующей задачи его не
заменяет. При старте API незавершённые задачи отмечаются прерванными. При импорте
одинаковых данных результат сохраняется (сравнивается fingerprint всех семи таблиц).
Изменение данных или `/infra-loader/delete-all` в той же транзакции меняет ревизию
и удаляет все задачи/результаты всех пользователей. Старый процесс может доработать
до своего timeout, но проверка ревизии не даст ему записать результат.

Frontend по умолчанию использует HTTP. На странице бригад серверный результат
перечитывается раз в 3 секунды; перед выгрузкой он проверяется повторно, поэтому
очищенный JSON нельзя снова скачать из старого состояния страницы. Mock доступен
только с явным `VITE_REPAIR_API_MODE=mock`.

## Запуск и проверки

`docker compose up -d --build` собирает API с Python-пакетом `algorithm/` из корня
репозитория. Dev Compose монтирует пакет в `/api/algorithm` только для чтения.
Модуль не читает дамп или внешнюю БД во время расчёта: вход готовит сервер.

```sh
docker compose exec -T api python -m unittest discover -s tests -p test_planning.py -v
docker compose exec -T api python -m unittest discover -s tests -p test_graph.py -v
python3 -m unittest discover -s algorithm/tests -v
docker compose exec -T frontend npm run test:operations
docker compose exec -T frontend npm run lint
docker compose exec -T frontend npm run build
```
