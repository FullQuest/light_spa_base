# Источники

[Карта API](../../README.md) · [Разработка](../../../docs/development.md)

Модуль получает JSON по HTTP GET вручную и по интервалу. Отдельных сервисов и зависимостей нет.
Сохраняется один последний успешный ответ; истории ответов и преобразования в документы пока нет.

## Файлы

| Файл | Назначение |
|---|---|
| [models.py](models.py) | Таблица `Source`, входные настройки и публичные ответы |
| [service.py](service.py) | GET-запрос, сохранение ответа/ошибки, защита от пересечения операций, цикл опроса |
| [scheduler.py](scheduler.py) | Запуск и остановка фонового потока через lifespan FastAPI |
| [schedule.py](schedule.py) | Расчёт ближайшего запуска по интервалу или календарю |
| [router.py](router.py) | API списка, карточки, настроек, ручного опроса и удаления |

## Доступ

Все запросы требуют `sources.view`. Создание, настройки, ручной опрос и удаление дополнительно требуют `sources.manage`.
Пользователи с правом просмотра видят данные всех источников. Отдельных доступов источника пока нет.
URL, тип авторизации и признак наличия токена доступны только управляющим.
Сам токен не возвращается даже управляющему; пустое поле при редактировании сохраняет его.
Переключение на авторизацию `none` удаляет токен. Если удалённый API отразил токен в JSON,
совпадающие строки заменяются на `[скрыто]` перед сохранением снимка.
Переходы по HTTP-редиректам не выполняются: укажите конечный адрес API.

Токен хранится в локальной SQLite-базе без шифрования. Не добавляйте рабочую БД в Git.
Настраивать URL могут управляющие источниками, включая адреса внутренних API.

## API

| Запрос | Результат |
|---|---|
| `GET /api/sources` | Список без полного JSON и настроек подключения |
| `POST /api/sources` | Создание настроек |
| `GET /api/sources/{id}` | Состояние, времена попыток и последний успешный JSON |
| `GET /api/sources/{id}/settings` | Настройки без токена, с флагом `has_token` |
| `PUT /api/sources/{id}` | Полное обновление настроек; пустой `token` сохраняет существующий |
| `POST /api/sources/{id}/poll` | Ручной опрос и актуальная карточка |
| `DELETE /api/sources/{id}` | Удаление источника вместе со снимком |

Настройки: `name`, `url`, `auth_type` (`none`/`bearer`), `token`, `interval_seconds`, `enabled`,
`schedule_mode`, `schedule_time`, `weekdays`.
Интервал — 1–86400 секунд, по умолчанию 300. Новый источник впервые опрашивается через интервал;
для немедленного получения данных используйте ручной запуск. Он работает и при `enabled=false`.

`schedule_mode=interval` сохраняет прежнее поведение. `schedule_mode=calendar` запускает опрос
в `schedule_time` (`ЧЧ:ММ`) по выбранным `weekdays`: 0 — понедельник, 6 — воскресенье.
Нужно выбрать хотя бы один день; по умолчанию выбраны все. Время фиксировано в МСК (UTC+3),
независимо от часового пояса браузера и сервера. Пример: `09:15`, `[0,2,4]` — пн/ср/пт в 09:15 МСК.
За один календарный день предусмотрен один запуск. Ручной опрос не переключает режим;
после него следующий запуск остаётся ближайшим будущим временем расписания.

Календарные настройки хранятся в отдельной таблице `SourceSchedule`; без записи используется интервал.
Существующие источники сохраняют поведение, обновление схемы их таблицы не требуется.
При переключении на интервал календарная настройка удаляется. При удалении источника она тоже удаляется.

Состояния: `never`, `success`, `error`. Ошибка удалённого API сохраняется в карточке;
ручной `/poll` возвращает 200 с `status=error`, а прежний снимок и время успеха остаются.
JSON `null`, массивы и скаляры допустимы. Наличие успешных данных определяется по `last_success_at`.
Сетевой таймаут — 5 секунд, максимальный ответ — 5 МиБ. Константы находятся в `service.py`.

## Таймер и перезапуск

Один поток API раз в секунду выбирает источники, которым пора обновиться, и опрашивает их последовательно.
Ручной и автоматический запуск используют одну функцию. Опрос, изменение и удаление одного источника
не пересекаются: занятый источник возвращает 409. Другие источники и HTTP-запросы приложения продолжают работать.
Следующий запуск рассчитывается после завершения попытки, включая ошибочную. Состояние хранится в SQLite,
поэтому просроченные задания возобновляются при запуске API. Выключение автоопроса очищает следующую дату.
Пропущенные календарные запуски не воспроизводятся по одному: выполняется одна попытка, затем выбирается следующее будущее время.

Реализация рассчитана на один процесс API (текущий запуск Uvicorn). Для нескольких процессов нужен общий
механизм координации или отдельный планировщик; создавать их заранее в заготовке не требуется.

## Интерфейс и отключение

`frontend/src/modules/sources/` содержит список, карточку, общую форму настроек и типы.
Карточка перечитывает состояние раз в две секунды; закрытый браузер не останавливает серверный опрос.
Флаг `features.sources` скрывает обе страницы. Чтобы отключить серверный модуль полностью, удалите
подключение роутера и аргумент `lifespan=sources_lifespan` вместе с соответствующими импортами из `main.py`.

## Проверки

[test_sources.py](../../tests/test_sources.py) проверяет опрос, таймер, ошибки, токены, права и пересечение запросов.
[test_bootstrap.py](../../tests/test_bootstrap.py) проверяет сохранение настроек и снимка после перезапуска.
[test_schedule.py](../../tests/test_schedule.py) проверяет дни недели, точное время и переход даты МСК/UTC.
Локальный тестовый API: `docker compose exec api python tests/source_fixture.py` (порт 9000 внутри контейнера).
Для подключения источника в том же контейнере используйте `http://127.0.0.1:9000/ok`.
Маршруты `/auth` (токен `fixture-token`), `/error`, `/invalid`, `/slow`, `/timeout`, `/null`, `/echo`
нужны для воспроизведения соответствующих сценариев. Это тестовый сервер, автоматически с приложением он не запускается.
