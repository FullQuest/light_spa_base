# Документы

[Карта API](../../README.md) · [Разработка](../../../docs/development.md)

Оригиналы хранятся в `storage/documents/<uuid>.<формат>`, метаданные и результат чтения —
в таблице `Document` в SQLite. Корневая папка `storage/` подключается к `/api/storage` через
Compose и исключена из Git. Для сохранности документов нужны и БД, и эта папка.

## Файлы

| Файл | Назначение |
|---|---|
| [models.py](models.py) | Таблица, краткий ответ для списка и полный ответ для карточки |
| [extract.py](extract.py) | Чтение форматов, декодирование текста и предупреждения |
| [service.py](service.py) | Сохранение оригинала, запуск чтения и фиксация результата |
| [router.py](router.py) | Загрузка, список, карточка, оригинал и удаление |

## Форматы

| Формат | Извлечение | Просмотр оригинала |
|---|---|---|
| TXT, MD | Текст; UTF-8, UTF-16 с BOM, резервное чтение Windows-1251 с предупреждением | Исходный текст без исполнения HTML/Markdown |
| CSV | Строковые ячейки в таблице; разделители: запятая, точка с запятой, табуляция, вертикальная черта | Исходный текст CSV |
| PDF | Текст по страницам, предупреждения о страницах без текста | Встроенный просмотр PDF, если поддерживается браузером |
| DOCX | Абзацы и таблицы основного текста в порядке документа | Скачивание исходника для открытия в редакторе |

OCR, восстановление вёрстки PDF, изображения, колонтитулы и вложенные таблицы DOCX не поддерживаются.
Таблицы PDF отдельно не извлекаются. Файл без доступного текста PDF получает ошибку с пояснением об OCR.
Точное оформление DOCX в браузере не воспроизводится.

## API и доступ

Все маршруты требуют `documents.view`. Для загрузки и удаления дополнительно нужен `documents.manage`.
Разрешения назначаются через редактор ролей; суперадминистратор получает их автоматически.
Доступ конкретного документа задаётся режимом: `all` (всем вошедшим с разрешением просмотра),
`roles` (выбранным ролям), `private` (только владельцу), `users` (конкретным людям).
Владелец (`uploaded_by`) и суперадминистратор сохраняют доступ при любом режиме.
Получатели могут читать и скачивать, но не меняют доступ и не удаляют чужие документы.
Владелец меняет доступ даже без `documents.manage`; удаление требует это разрешение.
Суперадминистратор может управлять любым документом. Проверки применяются и к оригиналу;
недоступный документ возвращает 404 и не появляется в списке.

| Запрос | Результат |
|---|---|
| `GET /api/documents` | Метаданные без полного текста и таблиц |
| `GET /api/documents/authors` | Авторы только доступных документов, независимо от активных фильтров |
| `GET /api/documents/access-options` | Краткие списки ролей и пользователей для настройки доступа |
| `POST /api/documents` | Загрузка `multipart/form-data`, поле `file`; возвращает карточку |
| `GET /api/documents/{id}` | Метаданные, текст, таблицы, предупреждения и ошибка |
| `PATCH /api/documents/{id}/access` | JSON: `access_mode`, `allowed_role_ids`, `allowed_user_ids`; владелец или суперадминистратор |
| `GET /api/documents/{id}/original` | Исходные байты; `?download=true` задаёт скачивание |
| `DELETE /api/documents/{id}` | Удаление записи и оригинала |

Чтение выполняется в запросе загрузки, без очередей. Состояния: `processing`, `ready`, `failed`.
При ошибке извлечения оригинал и запись сохраняются: POST возвращает 201 со статусом `failed` и полем `error`.
Неподдерживаемый формат возвращает 415, размер больше 20 МиБ — 413; эти файлы не сохраняются.
Повторная загрузка создаёт отдельный документ, даже если имя совпадает.

При загрузке режим и получатели передаются дополнительными multipart-полями `access_mode`,
`allowed_role_ids`, `allowed_user_ids`; для нескольких получателей повторяется имя поля.
По умолчанию доступ `all`. Списки сохраняются JSON-массивами, при смене режима неиспользуемый список очищается.
Выбор ролей и пользователей требует хотя бы одного существующего получателя.
Доступ по роли учитывает её актуальное назначение при каждом запросе.

Фильтры списка: `q` (часть имени без учёта регистра), `author_id`, `date_from`, `date_to`,
`format`, `status`, `mine=true`. Даты включают обе границы и трактуются в UTC.
Сортировка `sort=newest` (по умолчанию), `oldest`, `name`. Сначала ограничивается доступ,
затем применяются фильтры. Пагинации пока нет.
Фронтенд сохраняет фильтры в URL; ссылка возврата из карточки восстанавливает их.

Таблица создаётся при запуске. После изменения схемы одноразовую тестовую БД нужно пересоздать;
автоматического обновления существующих таблиц нет.

`text` — строка, `tables` — JSON-массив `{name, rows}`, `warnings` — JSON-массив строк.
Все ячейки сохраняются строками, первая строка не считается заголовком автоматически.
Оригинальное имя используется только для отображения и скачивания, путь генерируется из UUID.
`DOCUMENTS_DIR` задаёт каталог файлов при запуске API вне стандартного Compose.

Фронтенд находится в `frontend/src/modules/documents/`: список, карточка и общие типы.
Переключатель `features.documents` отключает обе страницы. Оригиналы загружаются с Bearer-токеном
и отображаются через временный Blob URL; токен не передаётся в адресе iframe или ссылки.

Проверки форматов, оригиналов, удаления, ошибок и разрешений: [test_documents.py](../../tests/test_documents.py).
