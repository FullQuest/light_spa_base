# Заявки — пример бизнес-модуля

[Карта API](../../README.md) · [Разработка](../../../docs/development.md)

Небольшой самостоятельный CRUD-модуль для копирования под задачи, обращения, поручения или инциденты.
Без универсальных конструкторов, вложений, комментариев и сложных переходов статусов.

## Файлы

| Файл | Назначение |
|---|---|
| [models.py](models.py) | Таблица `Request`, входные данные, публичный ответ и статусы |
| [router.py](router.py) | Запросы к БД, проверка исполнителя, CRUD и фильтры |
| `frontend/src/modules/requests/RequestsPage.tsx` | Форма создания, фильтры и список карточек |
| `frontend/src/modules/requests/RequestPage.tsx` | Карточка, редактирование и удаление |
| `frontend/src/modules/requests/RequestForm.tsx` | Общая форма создания и редактирования |
| `frontend/src/modules/requests/requests.ts` | Типы и названия статусов |
| `frontend/src/modules/requests/requests.css` | Стили модуля |

Таблица содержит ID, название, описание, статус, автора, исполнителя и даты создания/изменения в UTC.
Автор назначается сервером и не меняется при редактировании. Исполнитель необязателен;
выбирается из существующих пользователей, в том числе заблокированных с соответствующей отметкой.
Статусы: `new` (Новая), `in_progress` (В работе), `done` (Готово). Переходы между ними свободные.

## API и права

Все запросы требуют `requests.view`. Создание, изменение и удаление дополнительно требуют `requests.manage`.
Просматриваются все заявки; управляющий может изменять любую. Индивидуальных доступов здесь нет.

| Запрос | Назначение |
|---|---|
| `GET /api/requests` | Список, сначала новые |
| `GET /api/requests/assignees` | Краткие данные пользователей для выбора исполнителя |
| `POST /api/requests` | Создание: `title`, `description`, `status`, `assignee_id` |
| `GET /api/requests/{id}` | Карточка с именами автора и исполнителя |
| `PUT /api/requests/{id}` | Полное обновление редактируемых полей |
| `DELETE /api/requests/{id}` | Удаление |

Фильтры: `q` — часть названия или описания без учёта регистра, `status`, `assignee_id`,
`mine=true` — созданные текущим пользователем. Фильтры комбинируются, пагинации нет.
Фронтенд хранит их в URL и сохраняет при переходе в карточку и обратно.
При ошибке редактирования форма возвращается к сохранённым данным; ошибка создания сохраняет ввод.

## Как использовать как заготовку

1. Скопируйте `api/modules/requests/` и `frontend/src/modules/requests/` под новым именем.
2. Переименуйте модель таблицы и URL-префикс, измените поля и статусы в серверных моделях и клиентских типах.
3. Добавьте разрешения в `modules/roles/models.py` и обновите проверки нового роутера.
4. Импортируйте новый роутер до `create_all()` и подключите к `app` в `api/main.py`.
5. Добавьте страницы, ссылки и переключатель в `frontend/src/app/modules.ts`.

Страницы заявок отключены в текущей конфигурации интерфейса. Для отключения API удалите его импорт
и подключение роутера из `main.py`. Создание таблицы автоматическое; миграций существующей схемы нет.

Проверки CRUD, фильтров, автора и доступа: [test_requests.py](../../tests/test_requests.py).
