## Оптимизация

Целью алгоритма является минимизация времени от начала выполнения работ до момента полной ликвидации последнего активного инцидента. Иными словами, необходимо минимизировать момент времени, в который будет завершен последний из активных инцидентов.

При формировании решения необходимо одновременно определить:
- состав ремонтных бригад;
- распределение бригад между инцидентами;
- порядок выполнгения инцидинетов каждой бригадой

При выполнении решения необходимо учитывать эффективность различных вариантов распределения рабочих и ограничения, связанные с зависимостями между объектами.

## Результат работы алгоритма

Результатом работы алгоритма является JSON-файл установленного формата (см. в конце приложение M2), доступный для выгрузки через интерфейс приложения

Файл должен содержать:
- состав сформированных бригад;
- назначение каждой бригады на конкретные инциденты;
- порядок выполнения инцидентов каждой бригадой;

Время выполнения алгоритма - не более 180 секунд на предоставленном наборе данных.

## Проверка результата через сервис

Для проверки результатов участникам предоставляется отдельный сервис

Результат работы алгоритма может быть загружен в сервис. После загрузки сервис проверяет валидацию JSON-формата, соответствие правилам и рассчитывает общее время ликвидации всех инцидентов с учетом эффективности сформированных бригад. На основании результата проверки сервис отображает общее время ликвидации инцидентов.

Также сервис отображает текущий рейтинг комант, сформированный на основании результатов загруженных решений. В результирующей сетке отображены только лучшие баллы команд. Градация баллов от 0 до 100, где 100 - эталонное решение.

## Отображение результата

В приложении необходимо реализовать визуальное отображение результата работы алгоритма в виде иерархической структуры, обеспечивающей нагладное представление распределения инцидентов между ремонтными бригадами и последовательности ликвидации. На верхнем уровне должны отображаться ремонтные бригады, а прп раскрытии каждой бригады - назначенные ей инциденты, расположенные в последовательности планируемого выполнения работ. Пользователю должна быть доступна возможность просмотра списочного состава каждой укомплектованной бригады с указанием полной информации о каждом рабочем.

Для анализа результатов работы алгоритма также необходимо реализовать сводное расписание ликвидации аварии в табличном виде. Для каждого инцидента в расписании должны быть указаны: объект ликвидации аварии, номер события, тип ресурса аварии, время возникновения аварии, время начала ремонтных работ, планируемое время завершения ликвидации аварии, базовое время ликвидации аварии, фактическое время ликвидации аварии, а также номер ответственной ремонтной бригады. Расписание должно обеспечивать возможность наглядного анализа последовательности выполнения работ, занятости ремонтных бригад и планируемых сроков ликвидации всех активных инцидентов.

Также необходимо предусмотреть графическое отображение расписания в виде временной диаграммы с дорожками (swimlane timeline). По оси Y должны располагаться ремонтные бригады, каждая из которых представлена отдельной горизонтальной дорожкой. По оси X должно отображаться время выполнения работ. На дорожках в виде временных блоков отображаются инциденты, назначенные соответствующим бригадам, с указанием интервалов выполнения работ. Блоки, соответсвутющие инцидентам, должны визуально различаться по типу ресурса аварии. Диаграмма должна наглядно показывать последовательность выполнения работ каждой бригады, периоды ее занятости и ожидания, а также параллельное выполнение работ разными бригадами.

Структура выгрузки результата алгоритма (JSON)
```json
{
    "brigades": [
        {
            "brigade_id": 1,
            "employees": [100001, 100002, 100003],
            "event_order": [501, 503, 502]
        },{
            "brigade_id": 2,
            "employees": [100004, 100005],
            "event_order": [504, 505]
        }
    ]
}
```

- brigades - бригады
- brigade_is - ИД бригады
- employees - Таб.номера рабочих
- event_order - ИД событий в порядке их выполнения
