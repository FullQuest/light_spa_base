###Модуль 2. Черный ящик
##Общие положения
Чочтав предоставленных данных дополняется сведениями о доступных рабочих и их квалификациях, а также о среднем времени ликвидации аварии на объекте одним рабочим со средней квалификацией 5.0.
Входные данные, предоставленные участникам для разработки и отладки алгоритма, фиксируются до начала работы над модулем и остаются неизменными на протяжении всегор этапа разработки

Основная задача модуля: разработать алгоритм формирования ремонтных бригад и их распределения между активными инцидентами.

При проверке роботоспособности алгоритма используется новый набор входных данных, отличающийся от предоставленного на этапе разработки. В частности, изменяются:
+ Перечень объектов инфраструктуры
+ Структура зависимостей между объектами
+ Среднее плановое время ликвидации аварий для каждого объекта и типа ресурса.
(Важно, организаторы обещали удалять локальную БД по кнопке после каждого изменения входных данных)

При этом следующие данные остаются неизменными и полностью соответствуют данным, предоставленным на этапе разработки:
+ перечень рабочих
+ перечень квалификаций и уровни профессионализма рабочих;
+ матрица конфликтности между рабочими.

Таким образом, при проверке алгоритм участников должен сформировать новые оптимальные ремонтные бригады и определить порядок выполнения работ с учётом новых объектов инфраструктуры, зависимостей и времени ликвидации аварий, используя ранее полученную информацию о квалификациях рабочих и вычисленной степени их конфликтности.

Важно отметить, что должна быть предусмотрена возможность полного сброса системы с удалением загруженных данных. Это позволит начать работу с системой с нуля и использовать новый набор данных.

## Информация о рабочих

Для каждого рабочего предоставляются следующие сведения: табельный номер, фамилия, имя, отчество, дата начала стажа, перечень имеющихся квалификаций с обозначенным уровнем профессионализма по каждому виду работ.

Уровень профессионализма от 0.1 до 10.0

У рабочего может отсутствовать квалификация по отдельномму виду работ и один рабочий может иметь несколько квалификаций.


Информацию о рабочих следуют отобразить в приложении в отедльную таблицу для просмотра с фильтрами по ключевым полям.

## Формирование бригад

Для ликвидации всех активных инцидентов должны быть сформированы ремонтные бригады и определено их распределение между инцидентами.

Одна ремонтная бригада может быть назначена на несколько инцидентов, в том числе относящихся к разным видам работ. При этом бригада обязана выполнять назначенные ей работы строго последовательно: приступить к следующему инциденту она может только после полного завершения работ по предыдущему. Одновременное выполнение нескольких инцидентов одной бригадой не допускается.

На один инцидент может быть назначена только одна бригада. Один рабочий не может одновременно входить в несколько бригад. В составе одной бригады от 2 до 5 рабочих. Разные бригады могут работать одновременно, если это не противоречит зависимостям.

Для назначения бригады на инцидент в её составе должен присутствовать хотя бы один рабочий, имеющий квалификацию по виду работ, требуемому для ликвидации данного инцидента. Одна и та же бригада может назначаться на инциденты с различными видами работ при условии, что для каждого такого инцидента в составе бригады имеется рабочий с соответствующей квалификацией.

После формирования бригады её состав НЕ может измениться.

При формировании ремонтных бригад должны быть задействованы все предоставленные рабочие, без исключений. Каждая бригада должна быть назначена хотя бы на один инцидент.

Порядок выполнения инцидентов определяется с учётом зависимостей между объектами. Если объект A зависит от объекта B, инциден на объекте B должен быть полностью ликвидирован до начала работы на объекте A.

Зависимости транзитивны.

Бригада может ожидать завершения работ по другим инцидентам, даже если имеет возможность приступить к выполнению доступного инцидента, в случае если такое ожидание позволяет уменьшить общее время ликвидации всех активных интерфейсов.


## Эффективность бригады

Время выполнения работ зависимости от состава ремонтной бригады и квалификации её рабочих. Чем выше квалификация рабочего, тем быстрее выполняется работа

Использование нескольких рабочих с различными уровнями квалификации позволяет изменять время выполнения работ.

Между рабочими могут существовать конфликты, влияющие на слаженость работы бригады. Степень конфликтности между двумя рабочими задаётся матрицей и определяется значением от 0.0 до 0.9. Матрица конфликтности образует чёрный ящик.
Она постоянно скрыта, постоянна и может быть выявлена только через сервис проверки.

Если в составе бригады присутствуют конфликтующие рабочие, эффективность работы всей бригады снижается.

Степень конфликтности между рабочими A и B идентична степени между B и A.

Формула расчёта времени работы бригады над устранением аварии:
Tбриг = (Kmax + 1) * (Tбаза / (R1/5 + R2/5 + ... + R5/5))

где:
Kmax - максимальный коэф конфликтности среди всех пар рабочих бригад, независимо от наличия у них квалификации по поводу работ, требуемых для данного инцидента;
Tбаза - базовое время устранения аварии, соответствующее плановому времени ликвидации аварии одним рабочим (из бд).
R1, R2, ..., R5 - уровни квалификации рабочих, входящих в состав бригады.

При расчёте эффективности бригады для конкретного инцидента учитывается уровень квалификации каждого рабочего по соответствующему виду работ.
Если рабочий не имеет квалификации по требуемому виду работ, его уровень квалификации для данного расчёта принимается равным 0.

## Оптимизация

Целью алгоритма является минимизация времени от начала выполнения работ до момента полной ликвидации последнего активного инцидента. Иными словами, необходимо минимизировать момент времени, в который будет завершен последний из активных инцидентов.

При формировании решения необходимо одновременно определить:
- состав ремонтных бригад;
- распределение бригад между инцидентами;
- порядок выполнгения инцидинетов каждой бригадой

При выполнении решения необходимо учитывать эффективность различных вариантов распределения рабочих и ограничения, связанные с зависимостями между объектами.

## Результат работы алгоритма

Результатом работы алгоритма является JSON-файл установленного формата (см. в конце приложение M2), доступный для выгрузки через интерфейс приложения

Файл должен содержать:
- состав сформированных бригад;
- назначение каждой бригады на конкретные инциденты;
- порядок выполнения инцидентов каждой бригадой;

Время выполнения алгоритма - не более 180 секунд на предоставленном наборе данных.

## Проверка результата через сервис

Для проверки результатов участникам предоставляется отдельный сервис

Результат работы алгоритма может быть загружен в сервис. После загрузки сервис проверяет валидацию JSON-формата, соответствие правилам и рассчитывает общее время ликвидации всех инцидентов с учетом эффективности сформированных бригад. На основании результата проверки сервис отображает общее время ликвидации инцидентов.

Также сервис отображает текущий рейтинг комант, сформированный на основании результатов загруженных решений. В результирующей сетке отображены только лучшие баллы команд. Градация баллов от 0 до 100, где 100 - эталонное решение.

## Отображение результата

В приложении необходимо реализовать визуальное отображение результата работы алгоритма в виде иерархической структуры, обеспечивающей нагладное представление распределения инцидентов между ремонтными бригадами и последовательности ликвидации. На верхнем уровне должны отображаться ремонтные бригады, а прп раскрытии каждой бригады - назначенные ей инциденты, расположенные в последовательности планируемого выполнения работ. Пользователю должна быть доступна возможность просмотра списочного состава каждой укомплектованной бригады с указанием полной информации о каждом рабочем.

Для анализа результатов работы алгоритма также необходимо реализовать сводное расписание ликвидации аварии в табличном виде. Для каждого инцидента в расписании должны быть указаны: объект ликвидации аварии, номер события, тип ресурса аварии, время возникновения аварии, время начала ремонтных работ, планируемое время завершения ликвидации аварии, базовое время ликвидации аварии, фактическое время ликвидации аварии, а также номер ответственной ремонтной бригады. Расписание должно обеспечивать возможность наглядного анализа последовательности выполнения работ, занятости ремонтных бригад и планируемых сроков ликвидации всех активных инцидентов.

Также необходимо предусмотреть графическое отображение расписания в виде временной диаграммы с дорожками (swimlane timeline). По оси Y должны располагаться ремонтные бригады, каждая из которых представлена отдельной горизонтальной дорожкой. По оси X должно отображаться время выполнения работ. На дорожках в виде временных блоков отображаются инциденты, назначенные соответствующим бригадам, с указанием интервалов выполнения работ. Блоки, соответсвутющие инцидентам, должны визуально различаться по типу ресурса аварии. Диаграмма должна наглядно показывать последовательность выполнения работ каждой бригады, периоды ее занятости и ожидания, а также параллельное выполнение работ разными бригадами.
