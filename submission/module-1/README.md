# Модуль 1. Карта инфраструктуры

## Доступ к приложению

Адрес для локальной сети площадки: **http://192.168.19.12/graph**.
Вход в систему обязателен. Учётные данные суперадминистратора передаются отдельно.

Приложение разворачивается на выделенной машине с Docker Engine и Docker Compose v2.
Адрес `192.168.19.12` должен быть закреплён за сервером в сети площадки; для пользователей
нужно разрешить доступ к нему по TCP-порту 80.
Для работы интерфейса на рабочих местах достаточно современного браузера; устанавливать
дополнительное ПО на компьютеры пользователей не требуется.

## Запуск на сервере

Команды выполняются в каталоге проекта на сервере. Перед первым запуском создайте
локальный `.env`, задайте уникальный секрет и пароль администратора. Не включайте `.env`
в архив исходников и не передавайте его вместе с документацией.

```sh
test -f .env || cp .env.example .env
openssl rand -hex 32
```

Вставьте выведенный ключ как `SECRET_KEY` и отредактируйте остальные параметры:

```dotenv
SECRET_KEY=<случайный секрет из openssl>
ADMIN_LOGIN=<логин суперадминистратора>
ADMIN_PASSWORD=<уникальный пароль длиной от 8 до 128 символов>
REGISTRATION_ENABLED=false
```

Затем запустите приложение в штатном режиме:

```sh
docker compose -f compose.yaml up -d --build
docker compose -f compose.yaml ps
```

После запуска откройте `http://192.168.19.12/graph` с компьютера в той же сети и
проверьте вход под суперадминистратором. API и его документация доступны оператору
по адресу `http://192.168.19.12/docs`.

При первом старте приложение создаёт суперадминистратора из `ADMIN_LOGIN` и
`ADMIN_PASSWORD`. Эти параметры не меняют пароль уже существующего пользователя.
Поэтому смена пароля после первоначальной настройки выполняется отдельным скриптом,
описанным ниже.

## Настройки администратора

| Переменная | Назначение |
|---|---|
| `SECRET_KEY` | Секрет подписи токенов входа. Используйте длинное случайное значение. |
| `ADMIN_LOGIN` | Логин начального суперадминистратора; также используется скриптом смены пароля по умолчанию. |
| `ADMIN_PASSWORD` | Пароль только для начального создания аккаунта. Не сбрасывает пароль существующего аккаунта. |
| `REGISTRATION_ENABLED` | `false` отключает открытую регистрацию; новые учётные записи суперадминистратор создаёт в приложении. |
| `DATABASE_URL` | Необязательное подключение к базе. По умолчанию используется SQLite в `db/db.sqlite3`. |

Файл `.env` находится рядом с `compose.yaml`. После изменения настроек пересоздайте
контейнеры командой `docker compose -f compose.yaml up -d`. При смене `SECRET_KEY`
существующие токены входа перестанут приниматься.

## Смена пароля суперадминистратора

Скрипт запрашивает пароль в интерактивном режиме, проверяет совпадение и длину,
а в базу сохраняет только хеш. Выполняйте команду из каталога проекта на сервере:

```sh
docker compose -f compose.yaml exec api python -m scripts.reset_superadmin_password
```

По умолчанию скрипт выбирает логин из `ADMIN_LOGIN`. Для другого существующего
суперадминистратора укажите логин явно:

```sh
docker compose -f compose.yaml exec api python -m scripts.reset_superadmin_password --login admin@example.org
```

Скрипт откажется менять пароль, если аккаунт не найден или не имеет роли
суперадминистратора. Не передавайте пароль аргументом командной строки.

## Данные и обслуживание

- База данных хранится на сервере в `db/`; файлы документов — в `storage/`.
- Для резервного копирования остановите запись в приложение либо используйте согласованный
  снимок базы и каталога `storage/`. Храните копию отдельно от рабочей машины.
- Остановить сервисы: `docker compose -f compose.yaml down`.
- Запустить существующие контейнеры: `docker compose -f compose.yaml up -d`.
- Посмотреть состояние и журналы: `docker compose -f compose.yaml ps` и
  `docker compose -f compose.yaml logs --tail=100`.
- Команда `down` сохраняет данные в `db/` и `storage/`; не удаляйте эти каталоги при обновлении.

## Результат и проверка перед показом

Модуль предоставляет интерактивную карту объектов инфраструктуры: поиск, фильтры,
просмотр зависимостей, текущих состояний и событий, а также инструменты редактирования
представления карты. Интерфейс и API запускаются в Docker Compose и доступны через
веб-браузер по адресу выше.

В текущей версии API графа использует демонстрационный набор данных. Подключение
к производственной системе-источнику данных не заявляется. Перед показом на площадке
проверьте доступность `http://192.168.19.12/graph`, вход, загрузку карты и связь с API.

Перед передачей результатов дополните комплект архивом `source.zip`, содержащим
исходный код. Не включайте в него `.env`, базу `db/db.sqlite3`, пользовательские файлы
из `storage/` и локальные артефакты тестирования.
