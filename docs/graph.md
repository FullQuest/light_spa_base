# Граф объектов и актуальные события

Страница `/graph` доступна вошедшим пользователям. Фронтенд получает снимок графа
и событий через `GET /api/graph` примерно раз в секунду. Запросы не перекрываются,
таймаут — 2,8 секунды. В скрытой вкладке опрос приостанавливается, при возврате
и восстановлении сети возобновляется.

**Граф подключён к синхронизируемой локальной БД.** Модуль `infra_loader` читает
четыре таблицы из заданного внешнего PostgreSQL и атомарно заменяет их локальную
копию. Параметры подключения в `PG_URL` сохранены по условию проекта.
Общий для клиентов интервал попыток — 2 секунды (один процесс API); неизменившиеся
снимки не перезаписываются в локальную БД.
Ошибка подключения или некорректный импорт сохраняет прежнюю копию: API возвращает
`sourceStatus: stale` и время последней успешной синхронизации, в том числе после
перезапуска. Если первого снимка ещё нет, граф/архив возвращают HTTP 503.

Время `timestamp without time zone` во внешней БД трактуется как московское
(`Europe/Moscow`) при формировании ISO-8601. В локальной копии исходные даты
сохраняются без преобразования. Тип объекта (`station`/`consumer`) выводится
из наличия исходящих зависимостей: отдельного типа здания в исходной схеме нет.
Идентификатор ребра стабилен и составлен из ресурса и ID его концов.

Подробности локальной имитации PostgreSQL и проверки интеграции:
[database-integration.md](database-integration.md).

## Контракт графа

Основные точки обработки данных:

- `frontend/src/modules/graph/snapshot.ts` — типы ответа, проверка и нормализация.
- `frontend/src/modules/graph/useLiveGraph.ts` — URL запроса, параметр времени,
  интервал, замена снимка и согласование топологии.
- `frontend/src/modules/graph/EventsPanel.tsx` — выбор текущих событий объекта.

Пример полного ответа (ID передаются строками, включая ID событий из PostgreSQL):

```json
{
  "topologyRevision": "topology-1",
  "eventRevision": "events-10",
  "asOf": "2026-11-17T08:00:00Z",
  "syncedAt": "2026-11-17T07:59:58Z",
  "sourceStatus": "online",
  "objects": [{
    "id": "1", "name": "Станция №1", "kind": "station",
    "resources": ["water", "energy"], "district": "Центральный",
    "address": "ул. Мира, 1", "description": "Описание объекта"
  }],
  "dependencies": [],
  "currentEvents": [{
    "id": "10", "objectId": "1", "resource": "water",
    "occurredAt": "2026-11-17T07:30:00Z",
    "status": "incident", "statusName": "Авария",
    "description": "Повреждение оборудования"
  }]
}
```

- `objects`: стабильный `id`, `name`, `kind` (`station` / `consumer`),
  `resources`, `district`, `address`, `description`. Поле `district` API остаётся для совместимости, но не задаёт пользовательские районы в интерфейсе. Неизвестные строковые поля
  района/адреса/описания сервер передаёт пустой строкой, а не null.
- `dependencies`: уникальный `id`, `source`, `target`, `resource`.
  Направление: поставщик → зависимый. Ресурс должен присутствовать у обоих объектов.
  Граф должен быть ацикличным. Проверки фронтенда не заменяют серверную валидацию.
- Ресурсы: `water`, `energy`.
- `currentEvents`: последнее событие каждой пары **объект + ресурс**,
  у которого `occurredAt <= asOf`. При одинаковом времени побеждает больший
  числовой ID. Сортировка — новые сверху, затем ID по убыванию.
- `status`: `normal`, `maintenance`, `incident` — категорию определяет бэкенд
  по справочнику `event_statuses`. `statusName` — исходное название статуса;
  `description` — необязательный текст события.
- События нормализации/восстановления тоже входят в актуальный список.
  Предыдущие записи не показываются, но **не удаляются из БД**; полный список доступен
  в `/events/archive`, а временной снимок — на `/graph/archive`.
- Для ресурса без событий состояние `unknown` («Нет данных»). Не нужно создавать
  фиктивное событие «Норма». У вершины возможны несколько актуальных событий.
  Общий статус: авария → техработы → неизвестно → норма.
- Состояние и авария относятся к отдельному ресурсу объекта. Распространение
  активной аварии идёт только по направленным рёбрам с тем же ресурсом, транзитивно
  от источника к зависимым объектам. Обратного распространения нет. Последнее
  событие по ресурсу задаёт, активна ли авария; последующее событие нормы/работ
  снимает её из зоны.
- Для нового контракта `objects.states`, если прислан, игнорируется: состояния
  карточек и список событий строятся из одних и тех же `currentEvents`.
- `asOf` — момент запроса состояния. `syncedAt` — момент последней успешной
  синхронизации с внешним источником, допускает null. Эти значения НЕ взаимозаменяемы.
- `sourceStatus`: `online`, `stale` (отдаётся локальный кэш), `unavailable`.
  Фронтенд показывает состояние источника и время последней синхронизации.
- `topologyRevision` меняется при изменении объектов/связей; `eventRevision` —
  при изменении событий. Ответ — **полный атомарный снимок**, не дельта.
  HTTP-кэширование отключено на клиенте.
- Даты должны содержать часовой пояс, предпочтительно UTC с `Z`.
  Архив использует полный список событий для локального восстановления состояний
  и отключает периодический опрос графа.

Фронтенд требует полный снимок с `topologyRevision`, `eventRevision`, `asOf`,
`syncedAt`, `sourceStatus` и `currentEvents`. Неполный или некорректный ответ
отклоняется; предыдущий корректный снимок остаётся на экране с предупреждением.

## Обновление данных

Данные сервера хранятся только в памяти страницы, не в пользовательских настройках.
Ошибка HTTP/сети не очищает схему: остаётся последний корректный снимок с предупреждением.
Статус недоступной внешней БД приходит отдельно в успешном ответе сервера.
Внешнюю БД браузер не опрашивает; координация синхронизации между клиентами — задача бэкенда.

Обновление событий не запускает ELK, не создаёт новый Redux store, не сбрасывает
камеру, выделение, фильтры, пометки или режим редактора. Выделение события привязано
к объекту и ресурсу: при замене события новый актуальный элемент тоже подсвечивается.

При изменении топологии сохраняются позиции существующих объектов. Новые объекты
располагаются справа от существующих. Удалённые объекты убираются из скрытия и групп,
удалённые связи — из маршрутов. История undo при структурном изменении очищается,
чтобы не воскресить удалённые сервером данные. Пометки и камера сохраняются.
Помимо версии проверяется состав ID и концов связей на случай неверной версии от сервера.

## Управление и выделение

- Масштаб, перемещение, кнопки и интерактивная мини-карта.
- Поиск по названию и адресу работает по полному графу. Скрытый найденный объект
  показывается со сбросом фильтров и снятием его ручного скрытия.
- Фильтры ресурса, состояния, района и наличия аварий пересекаются. При скрытии
  объекта исчезают все его входящие и исходящие связи.
- Щелчок по вершине: объект и транзитивно зависимые, обход по полному графу
  (в том числе через скрытые вершины). Ресурс обхода задаётся отдельно.
- Ctrl / Cmd + щелчок: пользовательский район объекта (или сам объект, если района нет). Shift + щелчок: ручное выделение.
- Выбор вершины/результата поиска подсвечивает все её актуальные ресурсные события.
- Выбор события подсвечивает вершину и всех зависимых **по ресурсу этого события**,
  центрирует карту. Если вершина скрыта, показывает её со сбросом фильтров.
- События в правой панели не скрываются фильтрами карты; у скрытых объектов есть пометка.
  Так событие можно выбрать даже при выключенной видимости объекта.
- Дополнительные сведения об объекте — в левой панели.
- Активные аварии непрерывно выделяют свой фактический ресурсный конус: источник,
  достижимые зависимые объекты и только входящие в эти пути направленные связи.
  При наведении аналогично подсвечивается потенциальный конус объекта по каждому
  его ресурсу. Связи показывают красный движущийся пунктир со стрелкой поверх
  ресурсного цвета; источник и затронутые вершины получают красную подсветку.
  При уходе курсора временная зона пропадает; зоны активных аварий сохраняются.
  Пересекающиеся зоны объединяются, но resource пути не смешивают.

## Редактор и изгибы связей

Три режима: просмотр, редактирование графа и инструменты диспетчера.
В редакторе графа можно двигать вершины, менять маршруты, создавать пользовательские
районы из выделенных объектов, перемещать районы за заголовок и разгруппировывать.
Состояния, направления и состав связей менять нельзя.

Районы не формируются по адресам или полю `district` API. Один объект входит в один
район; создание нового района переносит выбранные объекты из прежних районов.
Развёрнутый район выделяется рамкой. Кнопка сворачивания доступна и на карте, и в
списке районов. Свёрнутый район представлен общей карточкой: внутренние рёбра скрыты,
все внешние входящие и исходящие связи перенаправлены к ней с сохранением ресурса и ID.
Параллельные связи сохраняются отдельно. Это только проекция: обход зависимостей,
расчёт индекса, события и серверная топология используют исходные объекты и связи.
Поиск или выбор события автоматически разворачивает район нужного объекта.
Редактировать маршрут спроецированной связи можно после разворачивания района.
Фильтр района работает по пользовательскому ID группы; старый адресный фильтр
сбрасывается при загрузке оформления. Группы старой версии с пересекающимся составом
приводятся к одному району на объект (более поздняя группа имеет приоритет).

Рёбра обозначены цветом ресурса, стрелкой и анимацией от источника к потребителю. Текстовые подписи рёбер убраны.
При системном предпочтении reduced motion анимация выключается. На карточках есть
цветные ресурсные метки с текстом: синий — вода, жёлтый — электроэнергия. Цвет состояния
остаётся независимым от ресурса.

Двойной щелчок по стрелке добавляет промежуточную точку; точки перетаскиваются,
двойной щелчок по точке удаляет её. По умолчанию углы сглаживаются квадратичными
кривыми. Переключатель «Вид связей» выбирает плавные изгибы или ломаные линии.
При перемещении вершины точки постепенно смещаются вслед за концами связи,
при одинаковом смещении обоих концов весь маршрут переносится целиком.

ELK Layered работает в Web Worker: ортогональная прокладка с последующим сглаживанием,
уменьшение пересечений без гарантии математического минимума. Расчёт ограничен 20 секундами.
При автораскладке ручные изгибы сохраняются и переносятся вслед за новыми концами.
Флажок «Заменить ручные маршруты при автораскладке» явно разрешает их заменить.
Автораскладка сохраняет группы и пометки, действие можно отменить.

## Инструменты диспетчера

Отдельный SVG-слой в координатах карты: произвольная кривая от руки, прямая,
прямоугольник и многострочная подпись. Цвет и толщина выбираются перед рисованием;
их также можно применить к выбранной пометке. Прозрачность пометок — 45%.
Инструмент выбора позволяет передвигать пометки, инструмент перемещения — карту.
Масштаб и мини-карта доступны в этом режиме. Пометки показаны на мини-карте
фиолетовыми маркерами их габаритов; точная форма штриха на мини-карте не воспроизводится.

Ластик целой пометки удаляет задетую пометку. Частичный ластик записывает круглые
маски вдоль жеста с интерполяцией между точками: стирает фрагменты линий, кривых,
прямоугольников и текста. Он не касается объектов или связей. Размер ластика задан
в экранных пикселях и остаётся удобным при любом масштабе. Маски привязаны к пометке,
двигаются вместе с ней и сохраняются после перезагрузки. Один жест — одно действие undo.
Старые подписи и линии читаются без обязательной миграции формата.

## Индекс зависимости

Индекс карточки рассчитывается по полному исходному графу, по всем ресурсам,
независимо от фильтров, скрытия и сворачивания районов. Число зависимых — число
уникальных достижимых по исходящим связям объектов без самой вершины. Общие
потомки и параллельные связи не увеличивают счётчик повторно.

Для `count = 0` индекс равен 0. Для максимального положительного `count` — 10.
Остальные: `max(1, min(9, round(10 * count / maxCount)))`. При отсутствии зависимостей
все индексы нулевые. В карточке показан индекс; точное число доступно в подсказке
и подробностях объекта. Это относительный показатель, при изменении топологии
его шкала пересчитывается. Дополнительных полей в ответе API не требуется.

## Фильтр событий и длительность аварий

Панель актуальных событий фильтруется независимо по состоянию и ресурсу. По умолчанию
показываются аварии и ремонтные работы, норма выключена. Фильтр меняет только список,
не снимок и не состояния карты.

На карточке ресурсы отображаются с собственным статусом: норма, ремонтные работы,
авария или влияние активной аварии. Собственная авария имеет красную маркировку,
объект под влиянием — отдельное оранжевое пунктирное обозначение, ремонтные работы —
жёлтое. Для собственной аварии время считается от `occurredAt` её актуального события.
Для затронутого объекта — от самого раннего ещё активного события-источника,
распространившегося на этот ресурс. При собственной аварии используется её собственное
время начала. Часы обновляются каждую секунду, формат `д ч мин с`.

Когда последнее событие ресурса перестаёт быть аварией, источник исключается из
расчёта; зависимые объекты пересчитываются по оставшимся активным источникам. Если
источников больше нет, маркировка влияния и таймер исчезают. Для источника показывается
подсказка с количеством уникальных прямых и косвенных зависимых объектов. Количество
не суммирует одну вершину повторно при нескольких путях.

## Хранение и проверки

Redux Toolkit + IndexedDB, ключ `user-{id}` внутри origin браузера. Сохраняются
позиции, маршруты, отметки ручного маршрута, вид линий, группы, пометки, фильтры,
ручное скрытие, камера, свёрнутость районов, цвет/толщина пометок и маски стирания. Серверных записей пользовательского оформления нет.
История последних 40 действий, выделение и режим редактора не сохраняются.
При недоступности хранилища показывается предупреждение.

React Flow, Redux Toolkit и React Redux — MIT; немодифицированный ELK.js — EPL-2.0.
Уведомления и ссылка на исходники: `/licenses/graph.txt`. React Flow Pro не используется.

```sh
docker compose exec -T frontend npm run lint
docker compose exec -T frontend npm run build
docker compose exec -T frontend npm run test:graph
```

артефакты в `.playwright-mcp/` не входят в Git.

## Временной архив схемы

Отдельная страница `/graph/archive` («Архив схемы» в меню) показывает историю
состояний на **текущей** топологии. Крупный заголовок «Архив» отличает её от живой
схемы. Доступны начало и конец периода с точностью до миллисекунд, сброс на весь
период, ползунок, стрелки назад/вперёд и воспроизведение с паузой/возобновлением.
Один шаг воспроизведения занимает секунду реального времени; на последней точке
проигрыватель останавливается. Повторный запуск с конца начинает историю заново.

Точки — уникальные фактические временные метки `occurredAt` из полного архива,
упорядоченные по возрастанию. Ползунок индексирует изменения, а не равномерные
отрезки времени: между соседними шагами может пройти секунда или несколько дней.
Одновременные события применяются одним шагом; список событий выбранной точки
можно раскрыть под шкалой. Границы периода включаются, пустой период и единственная
точка обработаны отдельно. Время отображается в часовом поясе браузера.

`GraphArchivePage.tsx` загружает `GET /api/events/archive` один раз, а
`useLiveGraph(..., false)` — текущую топологию и сохранённое оформление.
При перемещении по шкале API не опрашивается. `timeline.ts` восстанавливает
последнее событие каждой пары объект + ресурс на выбранный момент, включая
события **до начала периода**. При равных датах побеждает больший числовой ID.
Без предшествующего события ресурс имеет состояние «Нет данных». События объектов
или ресурсов, отсутствующих в нынешней топологии, не становятся текущими событиями
карты. Влияние аварий рассчитывается существующей логикой по направлению и ресурсу.
Состояния в браузерных проверках сверены с `GET /api/graph?at=...`.

Общий `GraphView` сохраняет геометрию при смене точки. Позиции, маршруты, районы,
свёрнутость, пометки и фильтры читаются из того же ключа `user-{id}`, что и на живой
схеме. В архиве остаются навигация, поиск, временные фильтры и выделение, но скрыты
редактор схемы и инструменты рисования. Изменения просмотра в архиве не перезаписывают
оформление живой страницы. Счётчики длительности аварий используют выбранный
исторический момент, а не текущее время компьютера. Панель справа показывает
последние ресурсные события на выбранный момент и синхронизирована с выбором вершины.

Полная история фиксируется при открытии страницы; для загрузки новых событий
страницу нужно открыть заново или обновить. История связей и оформления не ведётся.
При недоступности внешнего источника доступна сохранённая локальная история с явным
сообщением об этом.

## Разделение маршрутов и тема интерфейса

Авторaскладка использует отдельный входной и выходной порт для каждой зависимости.
`layoutModel.ts` задаёт одинаковые координаты портов для ELK и React Flow;
порядок детерминирован и не зависит от фильтров или текущих состояний. Слияние
рёбер отключено, увеличены отступы между рёбрами, объектами и слоями.
Это разносит параллельные ресурсы и ветвления вместо общего выхода из центра
карточки. Пересечения сложного графа возможны; отсутствие пересечений для любой
топологии не гарантируется.

Для уже сохранённой схемы примените «Редактирование графа → Автораскладка».
Ручные маршруты сохраняются и переносятся вместе с вершинами; для их замены
есть существующий флажок. Действие можно отменить. Свёрнутые районы продолжают
использовать проекцию внешних связей, исходные зависимости не изменяются.

В шапке находится переключатель светлой/тёмной темы. Первый выбор определяется
настройкой системы, явный выбор сохраняется в `localStorage` (`interface-theme`).
Тема применяется при старте приложения, включает карту, мини-карту, карточки,
архив и формы. При недоступности хранилища переключатель работает до перезагрузки.
