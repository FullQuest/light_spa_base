# Граф объектов — первая тестовая версия

Страница `/graph` доступна всем вошедшим пользователям. `GET /api/graph` требует
токен и возвращает детерминированный демонстрационный DAG: 120 объектов, 162 связи,
три района, вода и электроэнергия. Изменяющих методов у API графа нет.
Бэкап PostgreSQL не импортируется и не меняется; подключения к внешней БД пока нет.

## Контракт API

- `revision`, `demo` — версия набора и признак демонстрационных данных.
- `objects`: `id`, `name`, `kind` (`station` / `consumer`), `resources`,
  `states` (состояние отдельно для каждого ресурса), `district`, `address`, `description`.
- `dependencies`: `id`, `source`, `target`, `resource`. Направление: поставщик → зависимый.
- Ресурсы: `water`, `energy`. Состояния: `normal`, `maintenance`, `incident`.

Стабильные ID необходимы для сохранения пользовательского расположения при синхронизации.
Состояние карточки — наиболее серьёзное из состояний выбранных ресурсов
(авария → техработы → норма). В карточке подробностей показаны все ресурсы.

## Просмотр

- Колесо прокрутки перемещает карту, Ctrl + колесо масштабирует. Есть кнопки
  масштаба, вписывание всей схемы и интерактивная мини-карта.
- Поиск по названию и адресу работает по полному набору. Найденный объект
  центрируется. Если он скрыт, фильтры сбрасываются, ручное скрытие этого объекта снимается.
- Фильтры ресурса, состояния, района, наличия аварий применяются совместно.
  У скрытых объектов исчезают все входящие и исходящие связи.
- Щелчок выделяет объект и транзитивно зависимые объекты. Расчёт идёт по полному
  графу, а не только по видимой части. Можно выбрать ресурс обхода отдельно.
- Ctrl / Cmd + щелчок выделяет район. Shift + щелчок добавляет/убирает один объект.
- Дополнительные сведения открываются в боковой панели.

## Редактор

Режим «Редактировать схему» разрешает только изменение представления:

- перетаскивание вершин;
- группирование выделенных объектов, перетаскивание группы за заголовок, разгруппирование;
- двойной щелчок по стрелке добавляет точку маршрута; точки перетаскиваются,
  двойной щелчок по точке удаляет её;
- выбранную связь можно выпрямить;
- автораскладка ELK Layered с ортогональными связями и уменьшением пересечений;
- свободные подписи и линии: выбрать инструмент, щёлкнуть по свободному месту карты;
  подписи и начало линии можно перемещать, конец линии — перетаскивать;
- выбранную подпись можно изменить, любую пометку — удалить;
- отмена / повтор последних 40 изменений. Перемещения камеры не заполняют историю.

Объекты, состояния, направления и состав связей изменять нельзя. Delete и
переподключение стрелок отключены. Пометки не входят в граф зависимостей.
Автораскладка заменяет позиции и маршруты, сохраняя группы и пометки; её можно отменить.
ELK работает в Web Worker, расчёт ограничен 20 секундами с возможностью повтора.

## Локальные настройки

Redux Toolkit хранит текущее состояние, IndexedDB — настройки после перезагрузки.
Ключ `user-{id}` отделяет аккаунты в пределах этого origin браузера. Сохраняются
позиции, маршруты, группы, аннотации, фильтры, ручное скрытие, положение камеры.
История отмены, выделение и режим редактора не сохраняются. Серверных записей нет.
При недоступности IndexedDB пользователь видит сообщение; редактор работает в памяти.
При появлении новых объектов вычисляется раскладка, существующие пользовательские позиции сохраняются.

Это демонстрационный набор, а не данные из PostgreSQL. При подключении синхронизации
нужно определить актуальность событий, приоритеты ресурсных состояний и валидировать
DAG, включая длинные циклы. Текущая раскладка не гарантирует математический минимум пересечений.
Точки маршрутов заданы в абсолютных координатах; после перемещения объектов маршруты
при необходимости корректируются вручную или автораскладкой.

## Проверки

```sh
docker compose exec -T frontend npm run lint
docker compose exec -T frontend npm run build
docker compose exec -T frontend npm run test:graph
docker compose exec -T api python -m unittest discover -s tests -v
```

API-тесты проверяют авторизацию, доступ обычного пользователя, неизменяемость,
контракт ресурсов, уникальность связей и отсутствие циклов. Тесты фронтенда —
обход зависимостей, пересечение фильтров, состояния ресурсов, историю и изоляцию хранилищ.
Браузерные прогоны выполняются через Playwright MCP, локальные артефакты — `.playwright-mcp/`.
