КОНТРАКТЫ НЕПРИЛОЖЕННЫХ ФАЙЛОВ
Это справка по текущему проекту. Используй её как предоставленный контракт. При расхождении с приложенным кодом сообщи о расхождении и опирайся на код.

1. core.config.settings: SECRET_KEY обязателен из окружения, ALGORITHM = 'HS256', ACCESS_TOKEN_EXPIRE_MINUTES из окружения (по умолчанию 1440), REGISTRATION_ENABLED из окружения (по умолчанию true). ADMIN_LOGIN и ADMIN_PASSWORD используются при создании первого администратора. Значения по умолчанию не подтверждают локальные настройки пользователя.
2. core.db экспортирует engine и get_session(): with Session(engine) as session: yield session. В main.py вызываются create_all, init_roles и init_superadmin. Инициализация администратора пропускается при пустом логине или пароле и не меняет аккаунт, если такой логин уже существует.
3. В roles/models.py: Role содержит id: str (первичный ключ), name: str и permissions: list[str] в JSON-колонке. PERMISSIONS — словарь ключ → описание: users.manage, documents.view, documents.manage, sources.view, sources.manage, requests.view, requests.manage. RoleWrite принимает только права из каталога. Новые ключи добавляются в этот словарь; обычным ролям их назначают отдельно. Поведение superadmin и начальных ролей показано в приложенном roles/service.py.
4. Клиентский UserPublic = { id: number; email: string; full_name: string | null; role: string; role_name: string; permissions: string[]; is_active: boolean }. TokenResponse = { access_token: string; token_type: string }. Role = { id: string; name: string; permissions: string[] }.
5. auth/auth.ts экспортирует AuthContext и useAuth(). Контекст: user: UserPublic | null, loading: boolean, error: string | null, login(email, password): Promise<void>, register(email, fullName, password): Promise<void>, logout(): void.
6. app/App.tsx оборачивает содержимое в AuthProvider. Пока loading — загрузка; при error — ошибка с повторной загрузкой и переходом ко входу; при user — Layout, иначе AuthPage. main.tsx обеспечивает BrowserRouter. AuthPage использует функции контекста и получает доступность регистрации через getAuthConfig.
7. app/modules.ts содержит записи { path, title, Page, permission?, superadminOnly?, enabled?, menu? }. canOpenModule проверяет enabled !== false, роль superadmin при superadminOnly и наличие permission в user.permissions. Layout скрывает недоступные ссылки; для известного запрещённого маршрута показывает «Нет доступа», для отключённого или неизвестного — «Страница не найдена». menu: false скрывает ссылку, сохраняя маршрут. Это интерфейсные проверки; сервер защищает данные независимо.

Для последующих вопросов используй этот контекст. Небольшие дополнения к неприложенным файлам можно описать точными инструкциями, например добавлением ключей в PERMISSIONS.
