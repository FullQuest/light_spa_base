# Контекст для сессии в веб-чате

Каждый сценарий — готовый промпт и **8 исходных файлов**. В промпт уже включены сокращённая структура проекта и контракты вспомогательных частей. Отдельно загружать README и все файлы из импортов не требуется.

Код показывает основную реализацию, а справка описывает соседние механизмы: подключение модулей, новые права, сессию и маршруты. Для небольших добавлений модель сможет дать инструкции по справке. Для изменения самого механизма понадобится его актуальный исходник.

## Выбор сценария

| Задача | Стартовый промпт |
|---|---|
| Новая самостоятельная функция | [Создание модуля](new-module.txt) |
| Вход, сессия, роли и права | [Авторизация](authorization.txt) |
| Новое поле, фильтр, статус или исправление ошибки | [Изменение модуля](change-module.txt) |
| Оформление, главная, меню, формы, адаптивность | [Интерфейс](interface.txt) |
| Подключение внешнего JSON API, опрос и расписание | [Внешний API](external-api.txt) |

Выберите один основной сценарий. Все пять промптов в один чат загружать не нужно. Списки файлов и примеры следующих сообщений приведены ниже.

## Как пользоваться

1. Начните новый чат и вставьте содержимое выбранного `.txt` как сообщение. Промпт не нужно добавлять девятым вложением.
2. Приложите восемь файлов выбранного сценария. Все пути ниже — от корня проекта.
3. После всех материалов напишите отдельным сообщением `КОНТЕКСТ ПЕРЕДАН`.
4. Получите краткое подтверждение понимания, затем отправьте конкретную задачу.

Сохраняйте пути вложений. Если интерфейс показывает только одинаковые имена `models.py`, `router.py`, `service.py`, передавайте содержимое текстом с заголовками `FILE: api/modules/users/router.py`. Можно объединить исходники в один текст с такими заголовками; объём контекста от этого не уменьшится.

Справка в промптах — снимок текущих соглашений. После изменения общих механизмов обновите соответствующие пункты либо приложите актуальный код. В ходе сессии также передавайте новые версии изменённых файлов. Настоящие `.env`, БД и пользовательские загрузки для этих сценариев не нужны.

## Создание нового модуля

Промпт: [new-module.txt](new-module.txt).

| Приложить | Зачем |
|---|---|
| `api/modules/requests/models.py` | Таблица, входные данные, ответ и валидация |
| `api/modules/requests/router.py` | CRUD, БД, права, автор и фильтры |
| `frontend/src/modules/requests/requests.ts` | Клиентские типы и статусы |
| `frontend/src/modules/requests/RequestsPage.tsx` | Список, создание и фильтры |
| `frontend/src/modules/requests/RequestPage.tsx` | Карточка, изменение и удаление |
| `frontend/src/modules/requests/RequestForm.tsx` | Общая форма |
| `frontend/src/modules/requests/requests.css` | Оформление модуля |
| `frontend/src/app/modules.ts` | Точный реестр страниц и переключателей |

Вместо дополнительных вложений в промпте описаны `api/main.py`, `api/core/db.py`, проверки доступа, каталог прав, `useAuth` и `authRequest`. Поэтому модель видит цельный пример модуля и знает, как его подключить.

Список для копирования:

```text
api/modules/requests/models.py
api/modules/requests/router.py
frontend/src/modules/requests/requests.ts
frontend/src/modules/requests/RequestsPage.tsx
frontend/src/modules/requests/RequestPage.tsx
frontend/src/modules/requests/RequestForm.tsx
frontend/src/modules/requests/requests.css
frontend/src/app/modules.ts
```

Пример следующего сообщения:

```text
Добавь модуль «Оборудование»: список, карточка, создание,
редактирование и удаление. Поля: название, инвентарный номер,
статус, ответственный. Статусы: доступно, выдано, ремонт.
Просмотр и управление — отдельные права. Используй соглашения
проекта и выдай готовые изменения с путями файлов.
```

## Авторизация, сессия и права

Промпт: [authorization.txt](authorization.txt).

| Приложить | Зачем |
|---|---|
| `api/modules/users/models.py` | Пользователь и публичные схемы |
| `api/modules/users/router.py` | Регистрация, вход и профиль |
| `api/modules/users/service.py` | Пароли, создание пользователя, подготовка профиля |

В промпте описаны настройки, модель роли, клиентские типы, React-контекст, меню и маршруты. Основной путь авторизации показан реальным кодом.

Список для копирования:

```text

api/modules/users/router.py
api/modules/users/service.py
api/modules/users/dependencies.py
api/modules/roles/service.py

frontend/src/auth/AuthProvider.tsx
frontend/src/shared/http.ts
```

Пример следующего сообщения:

```text

пользователя с открытой вкладкой. Когда сервер перестанет принимать
запросы, когда обновится интерфейс и где это реализовано?
```

## Изменение модуля и исправление ошибки

Промпт: [change-module.txt](change-module.txt).

Набор для работы с заявками — 8 файлов: серверные схемы и CRUD, клиентские типы, страницы, форма и фактическая обработка HTTP-запросов и ошибок.

```text
api/modules/requests/models.py
api/modules/requests/router.py
frontend/src/modules/requests/requests.ts
frontend/src/modules/requests/RequestsPage.tsx
frontend/src/modules/requests/RequestPage.tsx
frontend/src/modules/requests/RequestForm.tsx
frontend/src/auth/api.ts
frontend/src/shared/http.ts
```

Для другого модуля замените шесть файлов requests на соответствующие модели, роутер, типы и затронутые страницы/формы; HTTP-клиенты оставьте. Укажите выбранный модуль в сообщении. Не нужно прикладывать все страницы, если задача касается только одной. Если существенная логика вынесена в service.py, включите его вместо незатронутой страницы. Для нетипичного модуля выбирайте 5–8 файлов, покрывающих нужный поток данных; это ориентир, а не требование скрывать необходимый код ради лимита.

Пример следующего сообщения:

```text
Добавь заявке приоритет: низкий, обычный, высокий. Существующие
заявки должны получить обычный приоритет. Покажи его в списке
и карточке, добавь выбор в форму и фильтр. Существующие данные
необходимо сохранить. Выдай изменения и способ обновления схемы.
```

Для ошибки вместо запроса на изменение передайте шаги воспроизведения, ожидаемый и фактический результат, сообщение ошибки или обезличенный ответ API. Промпт просит отличать установленную причину от предположений.

## Внешний API и источники

Промпт: [external-api.txt](external-api.txt).

Восемь файлов покрывают серверный опрос, оба режима расписания, типы, форму подключения и карточку. Описание поведения модуля включено прямо в промпт, поэтому отдельный README не требуется.

```text
api/modules/sources/models.py
api/modules/sources/router.py
api/modules/sources/service.py
api/modules/sources/schedule.py
api/modules/sources/scheduler.py
frontend/src/modules/sources/sources.ts
frontend/src/modules/sources/SourceForm.tsx
frontend/src/modules/sources/SourcePage.tsx
```

Следующим запросом передайте endpoint, HTTP-метод, тип авторизации без реального секрета, обезличенный пример JSON, нужные поля и частоту обновления. Документация внешнего сервиса — дополнительные материалы по конкретной задаче, а не часть стартового набора проекта.

Пример следующего сообщения:

```text
Нужно подключить GET /api/equipment внешнего сервиса с Bearer-токеном.
Обезличенный ответ: {"items":[{"id":"eq-1","name":"Ноутбук"}]}.
Достаточно хранить и показывать последний JSON, опрос каждые
300 секунд. Объясни, достаточно ли настроек существующего sources;
если да, укажи их без изменений кода. Адрес сервиса: [адрес].
```

Если задача требует POST, другой авторизации, пагинации, истории или записи результата в бизнес-таблицы, укажите это явно: этих возможностей нет в текущем механизме источников.

## Дополнительные файлы — после конкретной задачи

| Что меняется | Что может понадобиться |
|---|---|
| Сам механизм назначения или проверки прав | `api/modules/roles/models.py`, `api/modules/roles/router.py`, `api/modules/users/dependencies.py`, если ещё не приложен |
| Административный интерфейс | `api/modules/user_admin/router.py`, нужная страница из `frontend/src/modules/users/` или `roles/` |
| Форма входа | `frontend/src/auth/AuthPage.tsx`, при необходимости `auth.css` |
| Инициализация и настройки | Соответствующий файл: `api/main.py`, `api/core/config.py`, `api/modules/users/bootstrap.py` |
| Общая тема оформления | `frontend/src/index.css`, `frontend/src/app/app.css` |
| Проверки по образцу | `api/tests/test_auth.py`, для CRUD также `api/tests/test_requests.py` |
| Зависимости | `api/requirements.txt`, `frontend/package.json` |
| Интеграция с документами или источниками | README нужного модуля, затем его затронутые исходники |

Простое добавление ключей в PERMISSIONS или вызова include_router уже описано в промпте. Это само по себе не повод загружать все исходники управления ролями или сборки приложения. Полную замену неприложенного файла промпты запрещают: модель должна дать конкретное добавление либо запросить исходник, если он действительно нужен.
