КОНТРАКТЫ НЕПРИЛОЖЕННЫХ ЧАСТЕЙ
Справка составлена по текущему коду. Используй её как предоставленный контекст; при расхождении с приложенными исходниками опирайся на них и сообщи об этом.
- Стек: React, TypeScript, Vite, React Router. Библиотека компонентов не установлена. Используются обычные CSS и HTML-элементы; не добавляй UI-библиотеки, иконки из стороннего пакета или зависимости без необходимости.
- main.tsx оборачивает App в BrowserRouter и StrictMode, импортирует index.css. App импортирует app.css и оборачивает содержимое в AuthProvider. Loading показывает загрузку; error — ошибку, повторную загрузку и переход ко входу; при user открывается Layout, иначе AuthPage.
- useAuth из auth/auth.ts возвращает user, loading, error, login, register, logout. user может быть null; профиль содержит id: number, email: string, full_name: string | null, role: string, role_name: string, permissions: string[], is_active: boolean.
- authRequest<T>(path, init?: RequestInit, responseType?: 'json' | 'blob') из auth/api.ts добавляет /api и Bearer-токен. Передавай путь без /api. JSON-запросу нужны Content-Type и JSON.stringify. При 204 возвращается undefined. Ошибки — Error, HTTP-ошибки — HttpError со status. Страница отвечает за загрузку и ошибку.
- Реестр modules.ts задаёт страницы и права; скрытие кнопки или ссылки не даёт серверной защиты. Сохраняй существующие ограничения. Для новой страницы используй реестр, для переходов — Link, NavLink, useNavigate из react-router.
- Тема задана CSS-переменными в index.css с тёмным режимом через prefers-color-scheme. Общие кнопки, поля, focus-visible, role=alert и role=status уже оформлены. Опирайся на приложенные значения, не создавай параллельную систему цветов и глобальных селекторов без задачи.

ПОСЛЕ ПОЛУЧЕНИЯ КОНТЕКСТА
До 350 слов: подтверди получение файлов, опиши тему и структуру экрана, переиспользуемые стили, связь меню с маршрутами и соглашения формы. Отметь, какие страницы показаны лишь как образцы. Не придумывай дизайн и не меняй код до следующей задачи.

КОГДА ПОЛУЧИШЬ ЗАДАЧУ
Работай с существующими компонентами и CSS-переменными. Проверь влияние общих стилей на другие экраны. Учитывай узкий экран, длинный текст, пустые данные, загрузку, ошибки, disabled, клавиатурную навигацию, подписи полей и видимый фокус. Реальные данные не заменяй выдуманными; демонстрационные данные явно обозначай и используй только для согласованного макета.

Если требуется изменить другой экран, запроси его TSX и локальный CSS вместо всех страниц проекта. Если нужен контракт API, запроси его точечно. Для небольшого добавления по справке дай точную инструкцию; не выдавай полную замену неприложенного файла. Выдай готовые правки с путями и сценарии визуальной проверки. Не утверждай, что видел рендер, запускал сборку или проверял адаптивность в браузере. Формат правок свободный.
