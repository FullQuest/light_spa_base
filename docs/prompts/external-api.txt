Подготовь контекст сессии для подключения внешнего JSON API или изменения модуля sources в Light SPA Base. Конкретный сервис, пример ответа и задачу пришлю следующим запросом.

КОНТРАКТЫ И ГРАНИЦЫ
Это справка по текущему проекту. Для неприложенных частей используй её как контракт; при противоречии с приложенным кодом сообщи об этом и опирайся на код.
1. Стек: FastAPI, SQLModel, SQLite; React, TypeScript, Vite, React Router. Внешний запрос выполняется на сервере через urllib. Браузер обращается к нашему API, а не напрямую к внешнему сервису.
2. main.py импортирует модели через роутеры до SQLModel.metadata.create_all(engine). Роутер sources подключён через app.include_router(sources_router, prefix="/api"). Приложение создаётся с lifespan=sources_lifespan. core.db экспортирует engine и get_session(): with Session(engine) as session: yield session. Миграции существующих таблиц через create_all не выполняются.
3. require_permission из modules.users.dependencies проверяет текущие права по БД. Все маршруты источников требуют sources.view; изменение, ручной опрос, создание и удаление дополнительно требуют sources.manage. Права независимы. Пользователи с просмотром видят данные всех источников; индивидуальных доступов нет. Новые права добавляются в PERMISSIONS в api/modules/roles/models.py; superadmin получает весь каталог, остальным ролям права назначаются отдельно.
4. authRequest<T>(path, init?: RequestInit, responseType?: 'json' | 'blob') из frontend/src/auth/api.ts добавляет /api и Bearer-токен текущего пользователя приложения. Путь без /api. Для JSON явно задаются Content-Type и JSON.stringify. Ошибки бросаются как Error или HttpError со status; на 401/403 инициируется обновление профиля. Не смешивай этот токен с токеном внешнего сервиса в Source.
5. useAuth возвращает user, loading, error, login, register, logout. user может быть null и содержит permissions: string[]. Серверные endpoints источников требуют sources.view; страницы источников сейчас отключены в app/modules.ts. Не предполагай, что они доступны в меню.
6. Сейчас поддерживаются GET, JSON и авторизация none/bearer, хранится один последний успешный снимок. Истории, преобразования в документы, произвольных методов, OAuth-потока, обхода пагинации и нормализации в бизнес-таблицы в этом механизме нет. Если задача требует их, это отдельное расширение, а не существующая функция.
7. Настройки соединения доступны управляющим; токен не возвращается. Пустое поле при редактировании сохраняет токен, none очищает его. Токен хранится в SQLite без шифрования. Отражённые в JSON совпадения заменяются перед сохранением. Не запрашивай реальные секреты для подготовки решения.
8. Сервис хранит UTC без tzinfo; календарное расписание задаётся в МСК, UTC+3, дни 0–6. Один процесс API, один поток опроса, последовательная обработка источников. Блокировка в памяти координирует ручной опрос, настройки и удаление одного источника; занятость даёт 409. Не приписывай ей межпроцессную координацию.

ПОСЛЕ ПОЛУЧЕНИЯ КОНТЕКСТА
До 450 слов: подтверди файлы, проследи сохранение настроек → внешний запрос → снимок → карточку. По исходникам отметь таймаут и лимит ответа, запрет редиректов, расписание, блокировки и поведение при ошибке. Обрати внимание: /poll может вернуть HTTP 200 с status=error, сохранив прежний снимок; успешный JSON null определяется через last_success_at. Затем дождись задачи.

КОГДА ПОЛУЧИШЬ ЗАДАЧУ
Сначала определи, достаточно ли настроить существующий источник или нужно расширять код. Не меняй реализацию, если задача решается настройками. Для нового сервиса нужны endpoint, метод, схема авторизации без секрета, пример успешного ответа, нужные поля и частота обновления. Если это существенно для задачи и отсутствует, запроси документацию или обезличенные примеры. Не выдумывай контракт внешнего API.

Если нужно преобразование данных, отдельно опиши соответствие полей, идентификаторы, повторы и обновления существующих записей; запроси модели принимающего модуля. При расширении сохрани обработку ошибок, существующий снимок, разграничение прав и поведение расписания. Для точных изменений неприложенного кода запроси только затронутые файлы; небольшие добавления по контрактам допустимы как инструкции. Не выдавай полную замену неприложенного файла. Результат — готовые правки или настройки с путями и способом проверки. Не утверждай, что выполнял запросы или тесты. Формат свободный.
