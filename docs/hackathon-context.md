# Контекст на 18 ноября 2026

## Проект

Репозиторий хакатона по управлению инфраструктурой и ликвидации аварий. Модуль 1 —
карта инфраструктуры, её зависимости, текущие состояния и архив. Модуль 2 — просмотр
рабочих, формирование постоянных бригад, оптимизация и экспорт M2. Актуальное ТЗ —
[tz2.md](../tz2.md), текущий набор М2 — корневой `backup.sql`.

| Часть | Стек/состояние |
|---|---|
| Интерфейс | React 19, TypeScript 6, Vite 8, React Router, Redux Toolkit |
| Граф | XYFlow, ELK, редактор и авторазмещение, светлая/тёмная темы |
| API | FastAPI, SQLModel/SQLAlchemy, Pydantic, JWT, Argon2 |
| Данные | SQLite приложения; внешняя PostgreSQL инфраструктуры; локальный fixture в Compose |
| Запуск | Docker Compose, Nginx; dev API с reload, Vite |
| Рабочие/бригады | HTTP API по умолчанию, реальные рабочие и фоновые задачи |
| Оптимизатор | Пакет `algorithm/`, подключён через `api/modules/planning/algorithm_adapter.py` |

Реализованы схема и архивы, фильтры текущих событий, редактирование/раскладка графа,
синхронизация внешней инфраструктуры и очистка локальных данных. В М2 есть таблица
рабочих, фильтры/сортировка, XLSX, составы бригад, сводное расписание, временная
диаграмма, JSON, повторный расчёт и сохранение прошлого результата при ошибке.
Кнопка формирования запускает Python в отдельном процессе. Времена рассчитаны при нулевой матрице конфликтов.

Опорные файлы:

- [Граф](graph.md), [интеграция БД](database-integration.md) — граф и загрузка;
- [Рабочие и бригады](workforce-and-brigades.md) — UI М2 и предложенный контракт API;
- `api/modules/infra_loader/` — чтение внешнего источника и локальные снимки;
- `frontend/src/modules/workforce/`, `frontend/src/modules/brigades/` — UI, типы и mock;
- `frontend/src/modules/brigades/api.ts` — HTTP-транспорт;
- `api/modules/planning/algorithm_adapter.py:solve` — явная точка замены алгоритма;

- [План чёрного ящика](../algorithm/black-box-plan.md) — изучение скрытой матрицы.

## Правила бизнеса, которые нельзя потерять

Все рабочие используются ровно один раз. Бригада содержит 2–5 рабочих, получает минимум
один активный инцидент и не меняет состав. Каждая авария назначается ровно одной бригаде.
Для работы нужен хотя бы один сотрудник с нужной квалификацией. Одновременные работы
одной бригады запрещены. Зависимости транзитивны; бригады могут ждать предшественников.
Проверяется граф вместе с очередями, поскольку две по отдельности корректные очереди
могут вместе с зависимостями создать взаимоблокировку.

`T = (1 + Kmax) * Tbase / sum(R/5)`. Отсутствующий навык даёт 0; `Kmax` берётся среди
всех пар бригады. Цель — минимальный момент завершения последней аварии. На алгоритм
отведено до 180 секунд. Матрица скрыта, симметрична, постоянна, значения 0..0.9.
Текущая заготовка намеренно использует 0 для всех пар, но формула и интерфейс матрицы
уже поддерживают ненулевые значения.

При новом проверочном наборе изменятся объекты, зависимости и базовые времена;
состав рабочих, квалификации и скрытая матрица сохраняются. Старые ID событий и расписания
переиспользовать нельзя. В приложении синхронизируются также `employee`, `qualification`, `time_resolve`.
Backend при изменении данных меняет ревизию и удаляет задачи/результаты;
при одинаковом снимке сохраняет готовые планы. Очистка БД также удаляет планы.

## Контрольные данные и проверки

В текущем `backup.sql`: 28 рабочих, 42 квалификации, 45 активных инцидентов.
`test_brigades.json` и `tools/generate_test_brigades.py` — исходный валидный, намеренно
неоптимальный контроль: 7 бригад по 4 человека, порядок по зависимостям и round-robin.
Не подменять его результатом оптимизации. Новые файлы складываются в `algorithm/output/`.

```sh
docker compose ps
python3 -m unittest discover -s algorithm/tests -v
python3 -m algorithm --backup backup.sql --baseline test_brigades.json --seed 0 --iterations 200000 --time-limit 60 --report algorithm/output/report.json
docker compose exec -T frontend npm run lint
docker compose exec -T frontend npm run build
docker compose exec -T frontend npm run test:operations
docker compose exec -T frontend npm run test:graph
docker compose exec -T api python -m unittest discover -s tests -v
```

Браузерные проверки — через MCP Playwright с существующим Compose-стеком: вход,
рабочие и бригады, обе темы, узкий/широкий экран, расписание и диаграмма. Прогон UI
проверяет mock и оболочку; корректность независимого алгоритма проверяется Python-тестами
и отдельной оценкой M2. Локальные артефакты лежат в `.playwright-mcp/` и исключены из Git.
При обнаружении ошибки браузерного теста сохранять PNG в проект и сообщать абсолютный путь.

Приложение обычно доступно на `http://localhost/` или `http://localhost:8080/`, Vite —
`http://localhost:5173/`. Dev-порт API на этой машине переопределён в `.env`; секреты
и пользовательские базы в Git не добавлять. `pg_restore` на хосте отсутствует, CLI
умеет читать текущий локальный `backup.sql` через stdin запущенного `postgres-fixture`.
После замены файла bind mount уже работающего контейнера может указывать на старый файл:
для алгоритма не брать дамп по пути `/fixture/backup.sql` внутри контейнера.
