# Интеграция графа и PostgreSQL

`GET /api/graph?at=<ISO-8601 с offset>` и `GET /api/events/archive` доступны
всем авторизованным пользователям. Фронтенд использует существующий контракт без
дополнительных запросов к отдельным таблицам. Карта получает последние события
для каждой пары объект/ресурс на момент `at`; архив — все события без пагинации.
Равное время разрешается по большему числовому ID события.

Служебные `/api/infra-loader/*` доступны только суперадминистратору. `fetch-all`
принудительно запускает импорт, `delete-all` очищает только локальный кэш модуля.
Внешний PostgreSQL никогда не изменяется. Следующий запрос карты снова попробует
восстановить очищенный кэш из источника.

Импорт читает четыре таблицы в одной REPEATABLE READ транзакции PostgreSQL,
проверяет ресурсы, ссылки, DAG и категории статусов, затем заменяет локальные
данные в одной транзакции. Валидация или ошибка записи не уничтожает прежний кэш.
Самоссылки, как в исходном загрузчике, пропускаются. Параметры подключения
`PG_URL` оставлены заданными в коде. Timestamp без timezone интерпретируется как
`Europe/Moscow`; API отдаёт явный offset. Время последней успешной синхронизации
сохраняется в локальной БД.

В текущем Compose API запускается одним процессом. Lock и ограничение частоты
синхронизации общие для его потоков. При масштабировании на несколько процессов
понадобится вынести координацию синхронизации между ними в БД или отдельный worker.

## Проверка вне сети площадки

Дополнительный Compose-файл создаёт PostgreSQL 18 и восстанавливает `backup.sql`
в отдельный Docker volume. Он получает alias `as.start` только внутри сети
проекта, поэтому URL приложения менять не требуется. Порт базы наружу не открыт.
Этот вариант применяют только там, где настоящий `as.start` недоступен.

```sh
chmod a+r backup.sql tools/restore-postgres-fixture.sh
docker compose -f compose.yaml -f compose.override.yaml -f compose.postgres-test.yaml up -d --build
```

Для production-сборки локального стенда исключите `compose.override.yaml`.
Дамп восстанавливается только при создании нового volume. Запуск обычного
Compose без дополнительного файла не поднимает имитацию внешней БД.

На предоставленном дампе: 61 объект, 93 зависимости, 402 архивных и 86 актуальных
событий. Проверено появление нового события через периодический опрос без смены
координат/камеры, возврат исходного состояния, сохранение карты и архива при
остановке PostgreSQL, перезапуск API без источника и восстановление соединения.
Тестовая запись после проверки удалена.

```sh
docker compose exec -T api python -m unittest discover -s tests -v
docker compose exec -T frontend npm run lint
docker compose exec -T frontend npm run build
docker compose exec -T frontend npm run test:graph
```
