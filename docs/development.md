## Окружение и PyCharm

Dev-режим объединяет `compose.yaml` и `compose.override.yaml`: API работает с перезагрузкой,
Vite раздаёт интерфейс, Nginx направляет к нему запросы. Обычный режим использует готовую сборку
и отдельный образ фронтенда. После изменения зависимостей или Dockerfile пересоберите образы.

В PyCharm создайте две конфигурации Docker Compose с одинаковым именем проекта:

- обычная — только `compose.yaml`;
- dev — `compose.yaml`, затем `compose.override.yaml`.

Запускайте режимы по очереди. Порты прямого доступа в dev задаются через `API_PORT` и
`FRONTEND_PORT` в `.env` (по умолчанию 8000 и 5173).

## Где находится код

| Путь | Назначение |
|---|---|
| `frontend/src/app/` | Оболочка, маршруты и меню |
| `frontend/src/auth/` | Вход, регистрация и состояние сессии |
| `frontend/src/modules/` | Страницы отдельных функций приложения |
| `frontend/src/shared/http.ts` | Общий HTTP-клиент и ошибки |
| `api/` | [Серверные модули, БД и проверки доступа](../api/README.md) |

## Добавить страницу

Создайте `frontend/src/modules/tasks/TasksPage.tsx`:

```tsx
export function TasksPage() {
  return <section><h1>Задачи</h1></section>;
}
```

Импортируйте её в `frontend/src/app/modules.ts` и добавьте запись в массив `modules`:

```tsx
import { TasksPage } from '../modules/tasks/TasksPage';

// В массив modules:
{ path: '/tasks', title: 'Задачи', Page: TasksPage },
```

Одна запись подключает маршрут и меню. React Router обрабатывает переходы, прямые ссылки,
перезагрузку страницы и историю браузера. Для переходов внутри приложения используйте `Link`,
`NavLink` или `useNavigate` из `react-router`.

## Отключить страницу или скрыть ссылку

В `app/modules.ts` есть переключатели `features` для готовых разделов.
Для новых записей доступны следующие поля:

| Поле | Поведение |
|---|---|
| `enabled: false` | Страница отключена; прямая ссылка показывает «Страница не найдена» |
| `menu: false` | Только скрывает ссылку, маршрут продолжает работать |
| `permission: 'tasks.manage'` | Требует разрешение из профиля пользователя |
| `superadminOnly: true` | Допускает только суперадминистратора |

Без ограничений страница доступна всем вошедшим пользователям.
Эти поля управляют интерфейсом; API отдельно проверяет доступ на сервере.

Для карточки сущности добавьте маршрут без пункта меню:

```tsx
{ path: '/tasks/:id', title: 'Задача', Page: TaskPage, menu: false },
```

В компоненте `TaskPage` получите ID через `useParams()`.
Неизвестные адреса показывают «Страница не найдена», известные без разрешения — «Нет доступа».

## Подключить API к странице

Серверный роутер подключается по [инструкции API](../api/README.md#добавить-серверный-модуль).
На клиенте используйте `authRequest`:

```ts
import { authRequest } from '../../auth/api';

const tasks = await authRequest<unknown[]>('/tasks');
```

Клиент добавит `/api` и токен. Страница обрабатывает загрузку, данные и ошибки.
Для кнопок с ограниченным доступом проверяйте `user.permissions.includes('tasks.manage')`.

Поведение сессии и обработка ошибок описаны в [документации фронтенда](../frontend/README.md#сессия-и-запросы).

Логику и стили храните в папке модуля. Менять Nginx и Vite для нового `/api/...` не требуется.

## Проверки

Команды из корня проекта при запущенном dev-окружении:

```powershell
docker compose exec -T frontend npm run lint
docker compose exec -T frontend npm run build
docker compose exec -T api python -m unittest discover -s tests -v
```

API-тесты запускают отдельные процессы с временными БД, рабочие аккаунты не меняют.
Результаты ручных браузерных прогонов и временные стенды хранятся локально в `.playwright-mcp/`
и не входят в репозиторий.
