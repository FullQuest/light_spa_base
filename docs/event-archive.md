# Архив событий

Фронтенд-страница: `/events/archive`. Она загружает весь архив один раз при открытии
и выполняет фильтрацию на клиенте. Пагинации и периодического опроса нет.

## Контракт для backend

`GET /api/events/archive` (защищённый запрос текущего пользователя) возвращает полный
массив в конверте:

```json
{
  "events": [
    {
      "id": "9001",
      "objectId": "17",
      "objectName": "Насосная станция №1",
      "resource": "water",
      "occurredAt": "2026-03-04T10:15:00Z",
      "status": "incident",
      "statusName": "Аварийное отключение",
      "description": "Повреждение водовода"
    }
  ]
}
```

- `id` — обязательно строка, исходный ID события, не индекс строки.
- `objectId` — стабильный строковый ID инфраструктурного объекта.
- `objectName` — имя на момент отдачи архива; можно не передавать, тогда UI покажет ID.
- `resource`: `water` или `energy`.
- `occurredAt` — ISO-8601 с часовым поясом.
- `status`: `normal`, `maintenance`, `incident` — категория для оформления.
- `statusName` — тип/исходное название события из справочника, по нему работает фильтр типа.
- `description` — необязательная строка.

Ответ намеренно полный, как договорились для учебного проекта. При росте размера
архива API и UI потребуется перевести на серверные фильтры/пагинацию. Пока ответ
загружается только при переходе на страницу, без фоновых повторных запросов.

Кнопка «Все события объекта» в сведениях выбранной вершины открывает новую вкладку
`/events/archive?objectId=<id>`. Архив применяет этот фильтр сразу и позволяет снять его.

## Поведение интерфейса

Фильтры комбинируются: объект, точное название типа, ресурс, включительные локальные
календарные даты «С даты» и «По дату», поиск по ID события, ID/названию объекта,
типу и описанию. ID каждого события виден в таблице. По умолчанию показываются все
записи. Новые события сверху; при равном времени ID сортируются численно по убыванию.

Backend реализует endpoint на основе тех же локальных таблиц, что и граф.
При открытии архива выполняется попытка обновить общий кэш (не чаще раза в 5 секунд),
после чего возвращаются все события. Если источник недоступен, архив использует
последнюю корректную копию; до первой успешной загрузки возвращается HTTP 503.
Исходная БД не содержит описания события, поэтому `description` пока пустой.
