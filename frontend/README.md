# Устройство фронтенда

[Запуск приложения](../README.md) · [Добавление страниц и проверки](../docs/development.md) · [API](../api/README.md)

React отображает интерфейс, React Router обрабатывает URL, TypeScript описывает данные.
Общая сессия хранится в React Context, данные отдельных страниц — в их локальном состоянии.

## Как собирается интерфейс

`index.html` → `main.tsx` → `App` → `AuthProvider` → `AuthPage` или `Layout` → страница.

`App` показывает загрузку при восстановлении сессии, ошибку при сбое, форму входа без пользователя
и `Layout` после входа. `Layout` строит меню и маршруты из одного массива `modules`.
Настройки доступа влияют на интерфейс; API независимо проверяет права на сервере.
Поля конфигурации и примеры маршрутов описаны в [руководстве по разработке](../docs/development.md#добавить-страницу).

## Сессия и запросы

Компоненты получают пользователя и действия через `const { user, login, logout } = useAuth()`.
Токен хранится в `localStorage` под ключом `auth_token`, профиль — в состоянии `AuthProvider`.

- При открытии приложения сохранённый токен проверяется запросом `/api/auth/me`.
- При входе сначала получается токен, затем профиль; только после этого сессия сохраняется.
- Регистрация создаёт аккаунт и выполняет вход. Доступность регистрации приходит из API.
- Выход удаляет токен и очищает профиль.
- При возвращении фокуса в окно профиль перечитывается для обновления роли и разрешений.
- Ответы 401/403 из `authRequest()` вызывают событие `auth-refresh`, которое также обновляет профиль.
- Недействительный токен удаляется. При сетевой ошибке первоначальной загрузки токен сохраняется,
  а экран ошибки предлагает повторную попытку.

Путь защищённого запроса: страница → `authRequest()` → `request()` → `fetch('/api/...')` → API.
`authRequest()` добавляет токен, `request()` разбирает ответ и ошибки, страница отображает результат.
Тип вроде `authRequest<UserPublic[]>()` помогает проверке TypeScript, но не проверяет JSON во время выполнения.

## Данные страниц и формы

Страницы используют `useState` для данных и `useEffect` для первоначальной загрузки.
Флаги `active`/`cancelled` запрещают применять поздний ответ после ухода со страницы; запрос они не отменяют.

Значения полей читаются через `FormData` при отправке. `defaultValue` и `defaultChecked` задают
исходные значения, `form.reset()` возвращает форму к сохранённым данным.
После успешного изменения локальный список обновляется ответом API.
При ошибке редактирования значения откатываются; при ошибке создания введённые данные остаются для повторной попытки.
Форма нового пользователя появляется после загрузки ролей, чтобы роль `user` выбиралась корректно.

## Стили и сборка

- [src/index.css](src/index.css) — общие цвета, тема и типографика.
- `app/app.css`, `auth/auth.css` и CSS рядом со страницами — оформление компонентов;
  страница ролей использует `modules/users/users.css`.
- `public/` — файлы по прямым URL, например `/favicon.svg`; `src/assets/` — импортируемые ресурсы.
- [package.json](package.json) — команды и зависимости; `package-lock.json` фиксирует версии для `npm ci`.
- [vite.config.ts](vite.config.ts) — dev-сервер и прокси `/api` в контейнер API.
- `tsconfig*.json` — проверка TypeScript; [eslint.config.js](eslint.config.js) — правила качества кода.
- [Dockerfile](Dockerfile) — сборка в Node.js, затем раздача `dist/` через Nginx.
- [nginx.conf](nginx.conf) — возврат `index.html` для прямого открытия вложенных URL.
- `.gitignore` и `.dockerignore` — исключение локальных файлов из Git и Docker-образа.

Команды запуска находятся в [корневом README](../README.md#запуск), команды проверок —
в [руководстве по разработке](../docs/development.md#проверки).
